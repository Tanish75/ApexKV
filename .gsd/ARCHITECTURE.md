## Overview

**ApexKV** is an in-memory key-value store built in plain C++17 with zero third-party dependencies. It uses a separate-chaining hash table with dynamic resizing and load factor tracking. The system is designed to provide average O(1) CRUD operations, with upcoming extensions for write-ahead logging (WAL v2 with CRC32), snapshotting, time-to-live (TTL) expiration, and thread safety.

## Data Flow

```
[Write Path: put("user", 42)]
  1. Hash key: idx = std::hash<std::string>{}("user") % cap
  2. Inspect bucket[idx]:
     - If key exists: overwrite value, return false
     - If key absent: bucket[idx].push_front({"user", 42}), increment sz, return true
  3. Load Factor Check:
     - If (sz / cap) > maxLoad: trigger rehash(cap * 2)

[Read Path: get("user")]
  1. If cap == 0 or sz == 0, return std::nullopt
  2. Hash key: idx = std::hash<std::string>{}("user") % cap
  3. Iterate bucket[idx]:
     - If it->first == "user": return it->second
  4. Return std::nullopt

[Delete Path: remove("user")]
  1. Locate bucket[idx]
  2. Walk forward_list with prev and curr iterators
  3. Call bucket.erase_after(prev), decrement sz, return true
```

- [ ] **Test Gaps:**

  - Snapshotting with atomic rename not yet implemented.

## Conventions & Rules

- **Language Standard:** C++17, standard library only (`<forward_list>`, `<vector>`, `<string>`, `<optional>`, `<shared_mutex>`, `<chrono>`, `<cassert>`). Zero external dependencies.
- **Naming Style:** `snake_case` functions and local variables; member variables must use trailing underscore (e.g., `table_`, `cap_`, `sz_`, `max_load_`).
- **Complexity Philosophy:** 3rd-year CS student readability. No template metaprogramming, no complex abstraction hierarchies. Plain, explainable code.
- **Git Hygiene:** One small atomic commit per task with plain, descriptive commit messages.
